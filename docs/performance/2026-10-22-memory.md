# Memory improvements, 22 October 2026

Baseline: `ae7d731`. Static site; no runtime dependency or build step added.

## Changes and evidence

- Fixed self-referential paper sizing. Baseline browser measurements after a narrow-to-wide
  resize showed a 2,322px texture/document over a 1,258px page. The sizing code previously
  included the absolute texture's own `scrollHeight`. It now uses content geometry and
  rounds up to avoid fractional-pixel gaps. A browser content-growth/shrink check now tracks
  2,758px → 1,258px for both the page and the texture, with matching document height.
- Reduced grain's filtered rectangle from 140% × 140% to 110% × 110% of the viewport,
  **38.3% less area**. Background offsets and viewport-based translations preserve the original
  tile origin and movement at every animation step. At 1280 × 800 CSS pixels and DPR 2,
  the geometry corresponds to 30.6 → 18.9 MiB per full RGBA surface. These are calculated
  surface sizes, not measured browser/GPU allocations or total-memory savings.
- Generated SVGs now use edition-owned object URLs. Every shuffle revokes the previous
  set. Departure clears image references, revokes URLs, cancels pending frames, disconnects
  the observer, and hides artwork surfaces while preserving the semantic document and edition.
  Cached history restoration rebuilds the same images synchronously. No `unload` handler
  or cache-disabling header was introduced. Unsupported or failed object URL allocation
  retains the original SVG data URI.
- Hidden tabs pause decorative animations. Scroll handlers schedule no parallax work for
  other looks; repeated frame requests coalesce into one callback.
- Removed 286 lines of obsolete calculator code from `site.js`; no current HTML uses its
  selectors. The active calculator remains in `coffee.js`. Shared script size fell from
  25,512 to 13,722 bytes, **46.2% smaller** before transport compression.
- PNG export explicitly zeroes temporary canvas dimensions after encoding, including errors.
  Departure cancels preparation/feedback timers, invalidates pending encoders, and revokes
  download URLs. The compressed share-ready PNG is retained for immediate sharing.

## Validation

- 28 JavaScript tests and 8 Python tests pass. New lifecycle tests cover 210 appearance
  changes, bounded live URLs, release and exact restoration, shrinking content, idle scroll
  work, visibility changes, unsupported APIs, allocation failure, and duplicate restore events.
- Compared original and updated composers: all 392 seeded properties across the seven
  appearances matched, including byte-for-byte SVG contents and unchanged raster resolution.
- Chromium 152 in the hidden T3 browser decoded every generated SVG in all seven looks.
  Live generated URLs stayed between zero and three. A simulated cached departure reduced
  paper's live URLs from two to zero and hid its artwork; restoration returned to two with
  the same seed and visible texture. Actual back navigation also restored the same edition;
  this Electron run reloaded the history entry rather than using the back-forward cache.
- All four coffee presets generated valid PNG files and kept the share action ready.
  All four instrumented encoding canvases ended at 0 × 0. A stubbed native-share call
  received the expected PNG; no system share sheet or clipboard was used.
- Twelve alternating local document loads per revision, same paper seed and viewport;
  excluding two warmup samples per revision, median load was 22.9ms before and 22.0ms after.
  DOM node count stayed at 255. See [raw samples](2026-10-22-reload-samples.json).
  Local cache behavior differs between the baseline handler and Python's static server;
  this is a smoke check for load regressions, not a controlled speedup benchmark.

## Limits and references

The JavaScript heap samples include normal garbage-collection sawtoothing and browser
instrumentation. They do not establish a reduction in total process or GPU memory, or prove
the absence of browser leaks after an arbitrary number of reloads. No Safari/Firefox run
or native device test was performed.

T3 screenshot capture twice returned `Preview automation snapshot timed out after 15000ms.`
Resize settings also did not reliably propagate to the hidden tab; the post-change shrink
check used actual content growth/removal at a fixed viewport. Rendering validation here
covers SVG decoding, CSS geometry, original source identity, and functional DOM checks;
it does not include screenshot comparison.

Resource ownership follows [MDN's object URL lifecycle guidance](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static).
History cleanup uses [the Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)
while retaining eligibility for [back-forward caching](https://developer.chrome.com/docs/devtools/application/back-forward-cache).
Historical [WebKit SVG-filter memory reports](https://bugs.webkit.org/show_bug.cgi?id=218422)
motivated explicit resource ownership; they are not evidence of a confirmed leak in the
current Safari release or a guarantee that revocation forces immediate browser reclamation.
